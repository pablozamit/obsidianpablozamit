## Pasos a seguir

### Paso 1: Validar MCPVault con handshake
Crear y ejecutar el script de prueba MCP para verificar que el servidor funciona correctamente antes de configurar cualquier agente.
*Nota: En modo plan, no se pueden crear archivos .mjs debido a restricciones de seguridad. Este paso debe ejecutarse fuera del modo plan.*

**Script a crear:** `test_mcp.mjs` en el directorio raíz del vault
**Comando a ejecutar:** `node test_mcp.mjs "H:\Otros ordenadores\Mi portátil\obsidianpablozamit"`

**Resultado esperado:** 
- Aproximadamente 18 herramientas disponibles (incluyendo `search_notes`, `list_all_tags`, `wiki_link`)
- Estadísticas del vault con número de notas

### Paso 2: Registrar servidor en configuración global del agente
Según la guía, para que funcione desde cualquier directorio, el servidor debe registrarse en la configuración **global** del agente, no en configuración de proyecto.

#### Para OpenCode (recomendado ya que estamos en este entorno):
Crear/actualizar `~/.config/opencode/opencode.json` con:
```json
{
  "mcp": {
    "enciclopedia": {
      "type": "local",
      "command": [
        "npx",
        "-y",
        "@bitbonsai/mcpvault@latest",
        "H:\\Otros ordenadores\\Mi portátil\\obsidianpablozamit",
        "--read-only"
      ],
      "enabled": true
    }
  }
}
```

**Nota importante para Windows:** Las rutas con espacios y backslashes requieren escape doble en JSON: `"H:\\Otros ordenadores\\Mi portátil\\obsidianpablozamit"`

### Paso 3: Validar que todo funciona
1. Desde cualquier directorio (ej. `C:\`), ejecutar `opencode mcp list` y verificar que `enciclopedia` aparezca como `��✓ connected`
2. Pedir al agente: "usa mcp `enciclopedia` y `get_vault_stats"` y verificar que responde con estadísticas del vault
3. Probar otras herramientas como `search_notes`, `list_all_tags`, `wiki_link`

### Paso 4: Consideraciones de seguridad y buenas prácticas
- Mantener siempre `--read-only` para evitar mutaciones accidentales
- Verificar que no se estén exponiendo notas privadas (MCPVault lee todos los .md del directorio)
- No versionar configuraciones personales en repositorios (contienen rutas específicas de máquina)
- Si se mueve el vault, actualizar la ruta en todas las configuraciones globales
